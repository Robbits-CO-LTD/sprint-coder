詳しい話

インストールから最初のAI Teamまで

配布物をダウンロードするか、Node.js 22でソースから起動できます。Providerをまだ設定していなくても、Mock RuntimeでTask、Workspace、基本操作を確認できます。

最初は小さな検証用Projectを選び、Accessを「確認する」にして操作の流れを把握するのがおすすめです。重要なWorkspaceでは差分と承認内容を確認してください。

必要なもの

  • macOS、Windows、またはLinux
  • ソースから起動する場合はNode.js 22とnpm
  • Git repositoryを扱う場合はGit
  • 実AIを使う場合は認証済みCodex CLI / Claude Code CLI、またはProvider API key

Provider認証がなくても、Mock RuntimeでUIと基本的なTask操作を確認できます。課金を伴うAPIを接続する前の導入確認に利用してください。

インストールする

GitHub Releasesから取得

最新の正式版はv0.6.0（2026-10-24公開）です。OSに合うartifactを選びます。

OS配布物補足
Windows（installer） Sprint-Coder-Installer-0.6.0.exe 未署名のため、SmartScreenの警告が表示される場合があります
Windows（portable） Sprint-Coder-win32-x64-0.6.0.zip zip
macOS（Apple Silicon） Sprint-Coder-0.6.0-arm64.dmg 署名・公証済み
Linux（x64） Sprint-Coder-linux-x64-0.6.0.zip zip

OSの保護機能が警告を表示する場合があるため、release notesと配布状態を確認してください。対応OSや検証方法はリリース・ダウンロードにまとめています。

ソースから起動

Terminalで次の順に実行します（Node.js 22）。

  1. git clone https://github.com/Robbits-CO-LTD/sprint-coder.git
  2. cd sprint-coder
  3. nvm use
  4. npm ci
  5. npm start

nvmを使わない場合は、node --versionがv22.xであることを確認してください。

最初のTaskを作る

  1. 新規Taskを作成する：サイドバーから新しいTaskを作り、今回の仕事を独立した単位にします。
  2. Project / Workspaceを選択する：最初は検証用repositoryや小さなsample Projectを選びます。
  3. Model、Effort、Accessを確認する：Provider未設定ならMock Runtime、実AIを使うなら接続済みmodelを選びます。Accessは「確認する」から始めると操作境界を理解しやすくなります。
  4. 小さな依頼を送る：READMEの説明、簡単なコード調査、テスト実行など、結果を確認しやすい依頼から始めます。

Codex、Claude Code、API Providerを接続する

組み込みCLIは端末にあるCLIと認証を利用します。公式APIや互換APIは「設定 → モデルと接続」から追加し、接続検証後にmodel pickerで選択します。

API keyを登録する前に、接続先の料金、データ保持、rate limitを確認してください。Codex、Claude Code、Gemini、API、ローカルLLMの選び方と対応先の全体像はAIの選び方にまとめています。

ChatをAI Teamへ展開する

1体のAIとの会話で目的が明確になり、調査・実装・レビューを分ける価値が出たらTeamへ展開します。Leaderへ最終目的と、分担してほしい観点を伝えてください。

Worker数を増やすこと自体を目的にせず、ファイル担当、調査対象、review観点など境界を明確にすると成果を統合しやすくなります。詳しい流れはAIチームのしくみを参照してください。
