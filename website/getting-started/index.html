GETTING STARTED

Sprint Coderを始める

配布物をダウンロードするか、Node.js 22でソースから起動できます。Providerをまだ設定していなくても、Mock RuntimeでTask、Workspace、基本操作を確認できます。

最初は小さな検証用Projectを選び、Accessを「確認する」にして操作の流れを把握するのがおすすめです。early betaのため、重要なWorkspaceでは差分と承認内容を確認してください。

必要なもの

  • macOS、Windows、またはLinux
  • ソースから起動する場合はNode.js 22とnpm
  • Git repositoryを扱う場合はGit
  • 実AIを使う場合は認証済みCodex CLI / Claude Code CLI、またはProvider API key
まずMock Runtimeで試せます

Provider認証がなくてもUIと基本的なTask操作を確認できます。課金を伴うAPIを接続する前の導入確認に利用してください。

インストールする

GitHub Releasesから取得

公開済みのbuildがある場合は、リリース・ダウンロードからOSに合うartifactを選びます。early betaではOSの保護機能が警告を表示する場合があるため、release notesと配布状態を確認してください。

ソースから起動

TerminalNode.js 22
$ git clone https://github.com/Robbits-CO-LTD/sprint-coder.git
$ cd sprint-coder
$ nvm use
$ npm ci
$ npm start

nvmを使わない場合は、node --versionがv22.xであることを確認してください。

最初のTaskを作る

  1. 新規Taskを作成する

    サイドバーから新しいTaskを作り、今回の仕事を独立した単位にします。

  2. Project / Workspaceを選択する

    最初は検証用repositoryや小さなsample Projectを選びます。

  3. Model、Effort、Accessを確認する

    Provider未設定ならMock Runtime、実AIを使うなら接続済みmodelを選びます。Accessは「確認する」から始めると操作境界を理解しやすくなります。

  4. 小さな依頼を送る

    READMEの説明、簡単なコード調査、テスト実行など、結果を確認しやすい依頼から始めます。

Codex、Claude Code、API Providerを接続する

組み込みCLIは端末にあるCLIと認証を利用します。公式APIや互換APIは「設定 → モデルと接続」から追加し、接続検証後にmodel pickerで選択します。

API keyを登録する前に、接続先の料金、データ保持、rate limitを確認してください。対応先の全体像は対応AI・Providerにまとめています。

ChatをAI Teamへ展開する

一人のAIとの会話で目的が明確になり、調査・実装・レビューを分ける価値が出たらTeamへ展開します。Leaderへ最終目的と、分担してほしい観点を伝えてください。

Worker数を増やすこと自体を目的にせず、ファイル担当、調査対象、review観点など境界を明確にすると成果を統合しやすくなります。詳しい流れはAI Team Codingを参照してください。
