modelごとに別アプリを開くのではなく、同じTaskの中で「今回どの実行環境を使うか」を選ぶことがSprint Coderの基本です。利用できるtool capability、料金、データの送信先は接続方法によって異なります。

4つの接続方法

BUILT-IN CLI

Codex CLI / Claude Code CLI

端末にインストール済みのCLIと既存認証を利用します。

OFFICIAL API

各社の公式API

OpenAI、Anthropic、Google Gemini、xAIなどへ直接接続します。

COMPATIBLE API

OpenAI互換API

互換endpointを持つ複数Providerを共通形式で登録します。

LOCAL LLM

端末・LAN内のmodel

Ollama、LM Studio、LocalAIを利用できます。

すべてのmodelが同じ能力ではありません

利用可能なmodel、context、画像入力、tool use、Team実行などのcapabilityは接続先によって異なります。接続検証とmodel pickerの表示を確認してください。

Taskごとの選び方

  1. 既存契約やローカル環境を確認する

    すでにCodex CLIやClaude Code CLIを利用している場合は、組み込みCLIから始められます。

  2. 必要なcapabilityを確認する

    画像入力、tool use、長いcontext、特定modelなど、Taskに必要な能力を先に決めます。

  3. データ境界と料金を選ぶ

    クラウドAPIへ送るのか、ローカルLLMで閉じるのか、速度や費用と合わせて判断します。

  4. Taskへmodelを保存する

    選択はTaskの仕事単位と結び付き、次のTurnでも同じ前提で進められます。

料金とデータの送信先

Sprint Coder自体はMIT Licenseで公開されていますが、クラウドProviderのAPIやmodelには各社の利用料金が発生する場合があります。料金、rate limit、データ保持、学習利用の条件は接続先の最新規約を確認してください。

クラウドProviderを選んだTurnでは、生成に必要なpromptやcontextがそのProviderへ送信されます。完全にローカルで構成したい場合は、対応するローカルLLMを選択します。詳しくはLocal-firstと安全性を参照してください。
