# Robbits Countercheck

現在の依頼を正典とし、ユーザーが後から指摘しそうな欠落や過剰対応を先回りして反証する。過去の傾向は確認観点にだけ使い、現在の指示を上書きしない。

## 最初に行うこと

1. [反証パターン](references/critique-patterns.md)を読む。
2. 対象を `計画`、`実装差分`、`完了報告`、`UI・成果物` のいずれかに分類する。
3. 明示された目的、完了条件、禁止事項、変更可能範囲、人間判断、出力形式を固定する。
4. 対象ファイル、コード、画像、ログ、GitHub状態など、判定に必要な現物を読む。変化しうる外部状態はliveで確認する。

レビューは既定で読み取り専用とする。ファイル、Git、GitHub、ラベル、外部サービス、実行状態を変更しない。ユーザーが修正も明示した場合は、反証結果を確定してから適用中の実装skillへ渡す。

## 義務台帳を作る

依頼を次の4区分へ分ける。

- `必須`: 満たさなければ完了できない。
- `境界`: 禁止事項、対象外、承認、秘密情報、変更可能範囲。
- `証拠`: 必須項目を確認できる観測点。
- `将来`: 今回は実施しない改善、別Issue、Human Gate。

各必須項目へ `達成 / 未達 / 未確認 / 対象外` を付ける。計画、開始、依頼、成功予定を達成証拠にしない。将来項目を「未実装の欠陥」として指摘しない。

## 7つのレンズで反証する

1. **意図と境界**: 本来の目的を別の技術目標へ置き換えていないか。read-only、入力禁止、保存禁止、使用モデル、人間承認などを越えていないか。
2. **証拠と現在状態**: 主張と同じ対象・同じ版・同じ時点を直接確認したか。古いログ、別worktree、間接状態、成功予定を現在の証拠にしていないか。
3. **原因と失敗経路**: 症状を隠しただけではないか。再発条件、競合、切替、異常系、偽成功を説明できるか。
4. **完了と後始末**: 実装、必要な検証、公開、ラベル、マージ、close、readback、cleanup、引き継ぎのうち、依頼された終点まで届いたか。
5. **比例性と停止条件**: 小変更に無関係な全テストや全面設計を足していないか。逆に高リスク変更の直接検証を省いていないか。終わる条件があるか。
6. **UXと人間の体験**: 内部テストが通っても、利用者には消えた、飛んだ、見切れた、不自然、分かりにくい状態になっていないか。移動には空間的連続性があるか。長い情報を勝手に省略していないか。
7. **回帰と忘れ物**: 以前の決定、修正済み事項、追加依頼、非対象、再発防止が後続工程で消えていないか。

モデル名が分かる場合も、モデル名だけで判定しない。次の症状で補正する。

- 過剰化の症状: 受入条件外の成果物、故障仮説のない追加検証、レビューの反復、停止条件の消失。
- 忘れ物の症状: 完了宣言と義務台帳が対応しない、公開・readback・後始末が未確認、提案やPR作成で止まる。

## 指摘候補を反証する

各候補について、指摘を無効にする事実を最低1つ探す。

- 仕様どおり、明示的な対象外、将来計画、既存の別問題なら除外する。
- 具体的な失敗経路や利用者影響がない好み、nit、一般論は除外する。
- 同じ原因から出た指摘は統合する。
- 低確度の推測だけで作業を止めない。
- 追加テストを求める場合は「変更箇所 → 起こりうる故障 → そのテストが捕捉する理由」を示す。

重大で実行可能な指摘だけを最大6件残す。指摘ゼロを正常な結果として認め、水増ししない。

## 出力する

最初に次を短く示す。

- 固定した完了条件
- 確認した現物と時点
- 未達または未確認の義務

各指摘を次の形式で書く。

```text
[重大度] 短いタイトル
反証する主張: 完了・安全・品質について何を疑うか
根拠: 対象、時点、file:lineまたは実測結果
反証試行: 指摘を無効にする事実を何で探し、どう判定したか
最小対応: 範囲を広げずに閉じる一手
確度: 確認済み / 強い推定 / 弱い推定
```

重大度は `BLOCKER / HIGH / MEDIUM / LOW` とする。`弱い推定`は `STOP` の理由にしない。

最後を必ず次のいずれかで終える。

- `判定: STOP —` 次工程へ進めない検証済み阻害要因と、その解除条件。
- `判定: CONTINUE —` 完了とは言えないが、安全に続行できる残作業。
- `判定: PASS —` 重要な反証が残らず、依頼された次工程または終了へ進める理由。

## ログから観点を更新する

ユーザーが履歴の再学習・更新を明示した場合だけ [抽出スクリプト](scripts/extract_feedback.py) を使う。通常レビューで全ログを再走査しない。

スクリプトは集計JSONだけを出力する。発言本文、個別セッションパス、識別子、秘密情報を出力しない。集計結果だけで規則を自動変更せず、具体例を現物で確認してから参照文書を更新する。

通常の依頼を訂正傾向へ混ぜないため、`human_messages` と訂正・不満・強い再確認を含む `feedback_messages` を分け、カテゴリ集計は後者にだけ適用する。
