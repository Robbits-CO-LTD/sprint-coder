# Root Cause Guardrail

## 目的

bug/fix では「たぶんここ」を直さない。
原因が確認できるまでは **RCA Mode: Hypothesis only** として扱い、実装修正は止める。
実装に進めるのは **Root Cause Confirmed** になった後だけ。

---

## 適用条件

次のどれかに当てはまるときは、この Gate を最上位の hard gate として使う。

- bug 修正
- fix 指示
- regression / 再発修正
- E2E FAIL / テストFAIL修正
- 「直っていない」「まだ失敗する」「再現する」という報告
- 修正済みのはずの症状が残っているとき

新機能の通常設計だけなら、通常の設計レビューに進む。
ただし、途中で不具合や失敗症状を見つけたら、この Gate に戻る。

---

## RCA Mode: Hypothesis only / Root Cause Confirmed

### Hypothesis only

原因はまだ仮説。
この状態では、調査はできるが、修正実装はできない。

**許可する操作**

- 失敗症状の再現
- ログ、スクショ、テスト出力、network trace、DB状態の収集
- 関連コードの読み取り、grep、型定義確認
- 呼び出し経路とデータ経路の整理
- 代替原因の列挙と除外
- 調査用の一時ログ追加（修正と混ぜない。最終差分に残すなら理由を書く）

**禁止する操作**

- 原因未確定のまま実装修正に入る
- 「ついで」のリファクタや広範囲整理を始める
- 症状だけを消す暫定対応を入れる
- 同じ仮説で実装リトライを繰り返す
- 関係が未確認のファイルを広く変更する
- Root Cause Confirmed と言わずに完了報告する
- **外形症状だけで内部機構を断定する**（検索の空振り・UIの見た目・`git diff` の ± 記号などから、現物のコード/データ/ログを読む前に原因を断定形で書く）。初回診断は「〜の可能性」と仮説形にとどめ、現物確認後に断定へ昇格させる

### Root Cause Confirmed

A/B/C のうち **2カテゴリ以上** が YES、かつ D が YES の状態。
D は D1〜D4 の全項目が YES のときだけ YES とする。

Root Cause Confirmed になったら、原因箇所と原因経路に直接対応する **最小修正** に進む。

---

## Root Cause Confirmed YES/NOチェック

### A. 症状再現

- [ ] A1. 失敗症状を1文で説明
- [ ] A2. 再現手順または再現コマンドを記録
- [ ] A3. 修正前の失敗ログ/スクショ/テスト出力/network trace のいずれかを保存
- [ ] A4. 再現できない場合はその理由と代替証拠を明記

**AカテゴリYES:** A1 があり、A2+A3 または A4 が埋まっている。

### B. 原因箇所

- [ ] B1. 原因として扱うファイル:行番号を特定
- [ ] B2. 入力呼び出し経路原因行までのコードパスを説明
- [ ] B3. 同種の別経路類似実装を検索し関係/非関係を仕分け

**BカテゴリYES:** B1〜B3 が埋まっている。

### C. 独立した証拠

- [ ] C1. 実行ログ/失敗テスト/console/network/DB状態/型契約不一致など、コード読解以外の証拠
- [ ] C2. その証拠がBの原因行と矛盾しない
- [ ] C3. 代替原因を最低1つ以上除外

**CカテゴリYES:** C1〜C3 が埋まっている。

### D. 実装修正との接続

- [ ] D1. なぜこの原因でこの症状が出るかを1-3文で説明
- [ ] D2. 修正方針が原因行原因経路に直接対応
- [ ] D3. 無関係なリファクタついで修正を含めない
- [ ] D4. 修正後に同じ症状が消えたことを確認する検証手順がある

**D項目YES:** D1〜D4 がすべて埋まっている。

---

## 実装開始条件

実装に進む前に、次を満たす。

```text
Root Cause Confirmed =
  (A/B/C のうち 2カテゴリ以上が YES)
  AND
  (D項目YES)
```

満たせない場合は **Hypothesis only** のまま。
実装修正ではなく、再現・証拠収集・仮説切り替え・相談を続ける。

---

## Symptom Gone Gate

修正後は「コードを変えた」では完了にしない。
同じ症状が消えたことを、修正前と同じ観測点で確認する。

- 修正前に失敗した再現手順/コマンドを再実行した
- 修正前に残したログ/スクショ/テスト出力/network trace と比較した
- 期待する成功ログ、成功画面、成功レスポンス、テストPASSのいずれかを保存した
- 関連経路で同じ症状が残っていないことを確認した
- 失敗が別症状に変わっただけなら、完了にせず新しいRCAに戻る

無関係なテストが通っただけでは Symptom Gone ではない。

## 報告テンプレート

### RCA結果

```markdown
## RCA結果

- RCA Mode: Root Cause Confirmed / Hypothesis only
- 症状: <1文>
- 再現: <手順/コマンド/代替証拠>
- 原因箇所: <file:line>
- 原因経路: <入力/イベント/呼び出し経路>
- 独立証拠: <ログ/テスト/network/DB/型契約など>
- 除外した代替原因: <最低1つ>
- 修正方針: <原因行・原因経路への最小修正>
- 判定: A=<YES/NO>, B=<YES/NO>, C=<YES/NO>, D=<YES/NO>
```

### 修正後検証表

```markdown
| 検証観点 | 修正前 | 修正後 | 証拠 |
|---------|--------|--------|------|
| 同じ再現手順 | FAIL: <症状> | PASS: <結果> | <ログ/スクショ/出力> |
| 原因経路 | <失敗状態> | <期待状態> | <証拠> |
| 類似経路 | <未確認/失敗なし> | <影響なし> | <検索結果/テスト> |
```

## friendly-mode 例文

- 「まだ原因が確認できていないので調査を続けます。」
- 「原因はここまで絞れました。証拠が2つ揃ったので最小修正に進みます。」
- 「同じ症状が消えたことを、修正前と同じ手順で確認します。」
- 「これはまだ Hypothesis only です。実装ではなく、代替原因を1つずつ外します。」
