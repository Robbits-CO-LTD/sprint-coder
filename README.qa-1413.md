# Windows QA #1413

このブランチは #1413 の失敗表示を確認するWindows専用の開発ビルドです。リリースやmainへの取り込みには使いません。このブランチ専用の作業ツリーに、Node.js 22と通常の開発依存関係、Electron用SQLiteとNativeSafeFsが必要です。依存関係は検証より先に用意してください。検証開始後は開発サーバーのループバック接続だけを使います。

```powershell
node --version
& ./qa-1413.ps1
```

初回だけ、現在の作業ツリーの `apps/desktop/qa-1413-local` に、新しいQAプロファイルとSkill保存先を作ります。処理の途中で準備に失敗した場合は、既存プロファイルを使い回さず、新しい作業ツリーで準備してください。前回の下書きがある場合は、検証の成功条件が持続する同じQAデータを使います。個人利用のプロファイルや #1412 のデータは使いません。

## 確認すること

「QA #1413 下書きカードの失敗理由」がウィンドウに表示されます。会話と同じTurnにカードが2枚あります。

1. **QA 同名の下書き**の「1件のファイルを確認」を開き、利用者が「インストール」を押します。カード内に「Skillをインストールできませんでした。同名のSkillが既に存在します。」が表示され、カードは残ります。
2. **QA 保存先にない下書き**で、利用者が「破棄」を押します。カード内に「Skillの下書きを破棄できませんでした。対象が見つかりません。再読み込みしてください。」が表示され、カードは残ります。1枚目の失敗理由もそのまま確認できます。

この試験は承認の付与、外部サービスへの接続、AIの送信を伴いません。ウィンドウにそのためのボタンはありません。終了は通常のウィンドウの閉じる操作を使います。

## 製品との差分

- 初期データに終了済みの合成Taskを用意し、失敗条件を作った2件の下書きをRendererに渡します。実際の製品では下書きカードが新規作成イベントを受信して表示されます。
- 表示は製品のTimelineとSkillDraftCard、操作は製品のAppStore、Preload、MainのSkillSettingsServiceを使います。失敗を返す代用処理はありません。
- Mainは専用作業ツリーの固定プロファイル以外を使いません。製品IPCの入口は、合成Taskの履歴と、指定の下書きに対する指定の操作に限定します。外部ページを開く経路とプロバイダーの起動時検査を無効にしています。
- ローカルのビルド確認は `& ./qa-1413.ps1 -CheckOnly` で行えます。Electronは初期データを検証してウィンドウを開かずに終了します。
