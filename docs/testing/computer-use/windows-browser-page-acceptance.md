この文書は、人が Windows 実機で確かめる手順である。
受入結果ではない。全項目の初期状態は **未確認** とする。
共通の準備と証拠の扱いは [共通手順](README.md) に従う。

## 今の状態

**ブラウザの操作は、まだ有効ではない。** 有効化は PR F と #1100 の判断の後に行う。
PR A〜D（#1132・#1134・#1135・#1136）は、拒否と再確認の保護を追加した段階である。
今の build（実行するアプリの成果物）では、操作成功を受入条件にしない。
確認対象は観測、承認カード、ページ変更による古い許可の失効、入力の拒否である。
Electron 製アプリの窓に影響がないことも確認する。

origin は、通信方式・ホスト・ポートで決まるページの出所を指す。
sensitive は機密性が高い状態、unknown は安全性を判定できない状態を指す。
現行の分類器は、通常のページでも操作可能とは判定しない。
origin が読めたことだけで、安全なページとは扱わない。
supervised は、人の監督と承認を必要とする操作モードを指す。
その上限の承認カードが表示されても、ブラウザ操作の開放を意味しない。
observe_only は観測だけのモードであり、入力の許可には使えない。

入口で拒否された結果と、ページ変更の再確認で止まった結果は分ける。
必要な段階まで到達できなければ、その再確認の項目は BLOCKED とする。
制限を解除したり、内部状態を書き換えたりして先へ進めない。

## 実機での準備

1. 対象 build の commit、未 commit 差分、配布形式、Windows の版を記録する。
2. ブラウザ名と版を記録する。Chrome・Edge・Firefox は別々に記録する。
3. 普段の利用環境から分離したプロファイルを用意する。
4. 秘密情報のない試験用ページを用意する。以下では名前を P1・P2・P3 とする。
5. P1 と P2 は同じ origin の別タブにする。P3 は異なる origin にする。
6. 確認文を変更できるページと、機密欄を持つ合成ページを用意する。
7. ページの切替は人が画面から行う。実際の購入・送金・認証は行わない。
8. 対象の窓を選び、観測結果と操作モードを確認する。
9. 各項目の開始前に観測し直す。前の項目の承認を使い回さない。

試験用ページは fixture（再現用の合成データ）で用意する。
機密状態への変化は、分類器が sensitive と判定する fixture を使う。
単にページへ「機密」と表示しただけでは、その前提を満たさない。
読み取り専用の診断で前提を確認できなければ BLOCKED とする。
実 Provider を使う確認は、別途明示された許可がある場合だけ行う。

UIA は、Windows がアプリの要素を読み取ったり操作したりする仕組みを指す。
ページの同一性は origin だけでなく、Document（ページ要素）の識別情報と場所で照合される。
人の目では分からない照合や入力時点は、既存の受動的な診断を併用する。
診断が使えない場合も、入力が見えなかっただけで再確認を PASS にしない。
Chrome での結果を、Edge や Firefox の対応済みという根拠にしない。

## A〜D の確認項目

表の英字名は、調査メモの試験名案と照合するための識別子である。
自動試験の実行名を保証するものではない。
chunk は、長い入力を分けて送る一まとまりを指す。
背景の呼び出しは、対象を前面にせず UIA から操作することを指す。

| 項目 | 人が行う手順 | 期待 |
| --- | --- | --- |
| B-01 観測と拒否 | P1 を観測する。無害な欄への入力を依頼する。表示と拒否理由を確認する。 | 観測できても入力は許可されない。観測不能を操作成功にしない。 |
| B-02 supervised の上限のカード | 上限が supervised の対象で、承認を要する操作を依頼する。カードが出たら承認して戻る。 | カードの承認だけで上限が外れない。ページの拒否条件を通過しない。カードまで到達できなければ BLOCKED。 |
| B-03 タブ切替 `tab_switch_invalidates_pending_action` | P1 の観測後、保留中の操作がある間に P3 へ切り替える。その操作を続けようとする。 | 古いページの許可が失効する。P3 に入力しない。再観測・再判定が必要になる。 |
| B-04 同じ origin の別タブ `same_origin_other_tab_rejects_old_approval` | P1 の承認待ちに P2 へ切り替える。元のカードを承認して戻る。 | origin が同じでも旧承認を流用しない。P2 に入力しない。 |
| B-05 承認後の機密状態 `approval_return_rechecks_sensitive_surface` | 承認待ちのページを sensitive の fixture へ変える。カードを承認して戻る。unknown への変化も別に試す。 | 承認済みでも入力しない。人の操作への引渡し、または拒否となる。状態ごとに結果を残す。 |
| B-06 確認文の変化 `confirmation_change_invalidates_approval` | 同じ origin のまま、承認待ちに確認文または操作対象を変える。元のカードを承認する。 | 旧承認を使わない。変更後の対象へ実行しない。 |
| B-07 読取不能 `unreadable_origin_never_reuses_previous_origin` | P1 を観測した後、空のページや取得不能な fixture に切り替える。再観測して入力を依頼する。 | 古い origin を再利用しない。unknown として入力を拒否する。取得失敗の証拠を残す。 |
| B-08 入力の chunk の間の変化 | 無害な長文入力を用意する。chunk の境界でページを変え、残りの入力を確認する。 | 変化後の再照合で残りを止める。現行 build の入口の拒否だけでは、この項目は BLOCKED。 |
| B-09 背景の呼出し直前の変化 `background_page_change_blocks_commit` | 背景操作の準備後、呼出し前に対象タブを変える。前面の別窓も観察する。 | 対象ページの再照合で中止する。変更先にも別窓にも入力しない。呼出し前まで到達できなければ BLOCKED。 |
| B-10 Stop | 承認待ち、ページの再確認中、chunk の間でそれぞれ Stop を押す。その後、旧カードや保留操作を続けようとする。 | 停止後に新たな入力を送らない。旧承認で再開しない。各時点を別に記録し、到達不能な時点は BLOCKED。 |
| B-11 Electron の回帰 | VS Code など、従来操作できたアプリの無害な編集用窓を選ぶ。同じ条件で短文入力と Stop を試す。 | 従来の権限・承認条件で操作できる。今回のブラウザ照合を理由に拒否されない。Stop も機能する。 |

承認待ちを作れない場合、B-04〜B-06 の承認往復は BLOCKED とする。
同じ拒否画面を、タブ・確認文・機密状態の全項目の成功証拠に使わない。
B-08〜B-10 は、実際に変化や停止が起きた時点を確認する必要がある。
既存の計測手段でその時点を区別できなければ BLOCKED とする。
すでに送られた入力を、Stop が取り消すことは期待しない。
Electron の回帰確認では、ターミナルや認証欄を操作対象にしない。

## 結果の記録

| 状態 | 意味 |
| --- | --- |
| PASS | 必要な前提・操作時点・期待を証拠で確認した。 |
| FAIL | 前提が成立した状態で、実際の動作が期待に反した。 |
| BLOCKED | 制限、fixture 不足、計測不能などで必要な段階を確認できなかった。 |
| 未確認 | まだ試していない。PR F 待ちの項目もここに含める。 |

次の形で、項目・ブラウザ・操作時点ごとに記録する。

```text
項目 ID／状態: B-xx / 未確認
日時／Windows の版:
build の commit／未 commit 差分／配布形式:
ブラウザ名／版（Electron はアプリ名／版）:
操作モード／fixture ID:
手順／変化・停止の時点:
期待／実結果／拒否理由:
証拠の保存先／BLOCKED の理由／残件:
後片付け:
```

**URL・ホスト名・ページや窓のタイトルは記録しない。**
ページは P1・P2・P3、分類は sensitive・unknown などの状態だけで記録する。
画像にもアドレス欄、タブ名、窓タイトルが入らないようにする。
診断の生データを添付せず、許された最小限の状態と件数だけを残す。
build 成功や自動試験の成功を、実機の PASS に置き換えない。
