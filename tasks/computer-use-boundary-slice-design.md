## #333 protected runner library adapter

Add a library-only orchestration entrypoint adjacent to `verify-computer-use-final-gate.mjs`. It accepts independently measured callbacks from the protected caller, never a CLI argument or an input-evidence-owned field. The adapter calls `measureOwnedRunFacts(platform, expectedReleaseIdentity)` for Windows/macOS and `verifyParentAssertions(parentClosure, expectedReleaseIdentity)` for all required parent references. The latter returns an independently verified closure digest or no proof; it must not simply hash unverified input. Its input closure is a frozen JSON snapshot; callbacks receive separately frozen snapshots to prevent mutation after verification. The adapter validates the immutable evidence using the existing validator with the measured facts and verified closure digest, and preserves genuine `trustedWorkflowAttestationVerified` as a separate caller input. Missing callbacks, rejection, malformed measurement or mismatch fails closed; no producer text is reflected in errors. No CLI export/workflow flag enables trust. Regression uses callback stubs to prove invocation, mutation resistance, mismatches, partial coverage and absent attestation; it does not claim real signer/process/privacy measurement. Existing workflow connection and actual independently measuring producers remain explicit follow-on work.

Review question: Is this adapter a meaningful API boundary, given callbacks are necessarily supplied by an already protected runner? It removes repetitive caller assembly without claiming callback data is authenticated inside the library. Prefer retain existing validator as authority and do not mint `verifiedClosureSha256` from the input itself.

The callback release snapshot contains every validator binding: source commit/run ID, evidence run ID/attempt, Windows/macOS artifact names, Windows portable/installer names and their SHA-256 values, and the macOS package SHA-256. The callback must bind its independently measured facts/assertions to this exact run and artifact set. Commit and portable/macOS digests alone cannot distinguish a rerun or a substituted installer. The adapter supplies these pins; it still cannot authenticate callback implementations or prevent a trusted callback from ignoring them.

## #500 native-owned opaque ticket and V1 safety slice

Future ownership: native mints cryptographically random opaque ticket only after side-effect-free classification; native keeps canonical bindings and expiry in its own bounded store. Main sees opaque ID, classification and bounded preview/binding digests. Main acknowledgement carries ID + trusted activation outcome; it does not carry authorizing replacement bindings. Native dispatch obtains fresh trusted session/action/target/observation/cancel epoch/process generation/ruleset/focus/geometry/identity/Task/Turn context, reclassifies, compares every binding, atomically consumes then performs input. Stop/disconnect invalidates all; changed context consumes/refuses; no `allow_plan` bypass. Native never trusts a renderer/model-created ID, reported process identity or classification.

No new command/ticket store/authority will be added until native implementation can be validated. Initial meaningful code slice is existing Main handshake validation: strict legacy V1 handshake schema at the actual binding entrypoint, rejecting unsupported build mode/ruleset/classifier/lexicon claims, unknown fields, malformed primitives, missing version/platform/NAPI fields and mismatches before exposing capability. Existing native handshake output must be enumerated first so valid current V1 output stays compatible. No manifest schema/default migration, protocol message number or feature-flag change. Tests exercise real `loadComputerUseNativeBinding` mock-addon path with legacy success, all malformed/mode claims and flag-OFF cases, rather than an unused schema helper. If current native legitimately emits extra fields, whitelist exact measured legacy keys and validate their existing types; do not silently strip them. Gate remains V1 and no V2 activation is introduced.

This enforces current unsupported-mode fail-closed behavior; it does not implement the S4 ticket/native classifier feature. A future coordinated V2 version bump is required before accepting V2 handshake extensions. Windows can validate the Main boundary without rebuilding native; macOS host source output is checked read-only and existing CI runs platform tests. Native build/signing/OS permission setup remain on hold.
