## N1 native binding prerequisite on 2026-10-03

Scope: macOS native only. The addon now parses the dispatch payload itself, computes a payload digest before taking the session state lock, and computes a context digest from the observation snapshot read under that lock. The replay/conflict envelope is `computer-native-dispatch-envelope-v2`, which binds request id, session id, action digest (kept for Main correlation), payload digest, context digest, request cancel epoch and observation revision. The session also holds an immutable task id and turn id. Nothing user visible changes; this is only the base for later native-owned tickets and preflight (N2).

Design points:

- Canonical framing lives in the new pure header `computer_use_native_binding.h` (portable C++20, no CommonCrypto, Objective-C, N-API or hash code). Lengths and counts are 8-byte big-endian, optional values carry a presence byte, doubles are IEEE bit patterns with -0 normalized to +0, and NaN/Inf are never encoded (fail closed). Vectors keep order; `std::set` is iterated in its fixed order; the unordered `semantic_control_signatures` map is not encoded.
- Context contains only request values, fields fixed at session creation, and the snapshot read under the lock. Moving state (session cancel epoch, closed flag, input attempt counter, observation publication state, the process-wide cancellation epoch, a live process generation re-read) is deliberately excluded so a replay of the same request yields the same envelope. The digest is bounded (at most 160 visual patches) and calls neither N-API nor the OS under the lock; Cancel stays lock-free.
- StartSession requires non-empty `taskId`/`turnId` (at most 512 bytes: contracts `idSchema` is 128 UTF-16 units, at most 384 UTF-8 bytes, and `computer-turn:` plus the 256-byte native session id is at most 270). They are written once, when a new session is created under `mac_sessions_mutex` before pending registration. Reusing an existing session id with a different pair fails with `SESSION_ID_REUSE`; resume/refocus never writes them. Dispatch never reads taskId/turnId/ticket from its envelope, and neither dispatch results nor StartSession results expose Task/Turn or any digest.
- Limits that must not be over-read: native does not detect a Turn switch (it only holds the pair captured at creation), and the ruleset component of the context is the fixed placeholder `v1-builtin`, which is not attested and does not satisfy the ADR S4-4 ruleset binding.

Verification status: local TypeScript source-contract tests, typecheck, ESLint and Prettier only. The existing `computer-use-native.test.ts` envelope assertion moved from v1 to v2 and gained invariants. The protocol harness gained canonical injectivity checks (colliding string pairs, empty vs absent, -0/+0, count shift, every field changing the output, determinism, NaN/Inf fail closed, Task/Turn validation). The reservation seam now compiles the production binding header via `-I` and checks payload-only and context-only changes under the same request id produce `native_request_id_conflict`, same-request replay, busy/cancel/async-failure behavior, and that request-supplied taskId/turnId do not change behavior. The seam digest is an identity stub, so it cannot prove SHA behavior and must not be given a hex-digest check on the internal digests. `StartSession` is compiled but is not executed by the seam or the harness: only its pure helpers (id validation/comparison) are exercised, and the actual call path remains unexecuted. Native compilation, harness and seam execution are NOT_RUN locally and depend on ordinary macOS/Windows CI at the final head. No ticket store, preflight export, handshake, Main/loader/contracts/UI, flag, eligibility, Windows host, dependency, build or signing change; #500/#387/#333 remain open.

## N2a native preflight and single-use ordinary ticket on 2026-10-03

Scope: macOS native only (Issue #500 N2a, Risk A, independent design review APPROVE_WITH_CHANGES with every item reflected). Main, the loader, types, contracts, UI, flag, handshake, manifest and the Windows host are unchanged, and Main neither calls `preflight` nor sends a ticket, so every production path behaves as before. #500/#387/#333 stay open.

What was added:

- New pure header `computer_use_native_ticket.h` (portable C++20, no platform header, hash, random source, clock or N-API): `NativeOrdinaryTicketBinding` (session id, request id, action digest, payload digest, context digest, cancel epoch, ticket generation) and a one-per-session `NativeOrdinaryTicketSlot`. The clock is injected as a monotonic nanosecond value. TTL is 5 s with a 10 s hard maximum, an overflowing expiry fails the issue, a clock that goes backwards (`now < issued`) or `now >= expires` is invalid, the token is 64 lowercase hex characters compared in constant time at a fixed length, `Issue` replaces the slot (and any failed issue also empties it), `Consume` destroys the ticket before it returns whatever the outcome (a failed check burns it), and `InvalidateIfGeneration` only drops its own generation. Generation 0 and owner 0 are "none" sentinels and are never issued. No approval ticket type exists.
- Async `Preflight` N-API (`napi_default`, placed between `Dispatch` and `Cancel`). It reuses `ParseNativeDispatchRequest` under the state lock and reports `decision` `ordinary`, `blocked`, `takeover`, `replay` or `denied` with the fixed keys `decision, reasonCode, deniedResult, ticket, classifierVersion, inputAttemptCount, requestId, sessionId, cancelEpoch, observationRevision`. Only a replay hit whose envelope matches is `replay` (no ticket); a changed envelope is `denied/native_request_id_conflict`; in-flight and a second concurrent preflight (one per session, and none while a dispatch is in flight) are denied. Reservation advances the ticket generation and records it as the owner; the ticket is minted and issued in the worker under the state lock (TTL starts at issue time) only when not closed, the cancel epoch is unchanged and the generation is still the owner. Every failure route releases the owner only when it is still this preflight's (Promise/work create/queue failure, completion status not ok including a worker that never ran, worker exception, which is a plain denial and never `unknown_effect`).
- General `Dispatch` captures the own `ticket` key once, outside Parse and outside the state lock, as plain values (`napi_has_own_property`; getters/Proxies cannot re-enter under the lock; the prototype is never consulted). Reserve order is replay, in-flight, ticket consume, busy, insert. A key that is present with any value (null, empty, non-string, wrong length) never falls back to the legacy path: it burns the slot and returns `rejected/native_ticket_invalid` with no effect. Replay and in-flight hits are answered before the ticket and never touch the slot, so even a bad ticket returns the cached result. No ticket key means the legacy behavior. N2b note: a "ticket required" rule must be placed after the replay/in-flight checks. A reservation that goes on to run also advances the generation and clears the slot.
- `ticket_generation` (atomic) advances lock-free in `Cancel` and `CloseSession` (Cancel never takes the state lock) and under the state lock in the observation publish, `StartSession` resume/refocus, every reservation and every preflight reservation. The close drain clears the stored secret and the owner. Entropy is `SecRandomCopyBytes` only (no weak fallback; failure means denied). The clock is `clock_gettime_nsec_np(CLOCK_MONOTONIC_RAW)`. Discarded tokens are scrubbed. Payload/context digests live in the request struct and are never returned.

Limits that must not be over-read:

- **The preflight is a SUBSET of the dispatch classification guards, not identical to them.** It runs `RevalidateBoundTarget`; for semantic actions `FindBoundSemanticTarget` (retained element released); for click/scroll the point classification, the observed control signature and the fresh visual patch check; for type/key the focused-element classification and observed signature. It does not read toggle state, validate selection values or text, create events or take any effect (no `CGEventPost`, AX perform/set, activation or `input_api_attempts` increment). After a ticket is consumed the dispatch worker still runs its full existing re-classification and every guard (`RiskOutcome` included); the ticket is a typed preflight proof, not permission to skip a guard. The existing `Perform*` functions are not modified (the source-contract test pins their digests).
- The receipt table is closed (every reason/result pair is listed in `kNativePreflightDeniedTable` or is a classifier blocked/takeover pair, and `SealNativePreflightReceipt` replaces anything else with `denied/native_dispatch_failed`). It does not attest S4's effect classifier, ruleset, Turn switching or E1-E5 precision.
- Seam evidence is simulated: the reservation seam compiles the production Parse/Reserve/Dispatch/Preflight/Issue/Release/Complete bodies and the production ticket header with an inert ticket-key read, CSPRNG, clock and classification, and its `StringDigest` is an identity stub (it proves production comparison/ownership logic, not SHA or real AX/CG behavior). The Cancel/Close assertions are only the generation increment and the drain clearing the slot and owner (the cancellation seam compiles the real `Cancel`/`CloseSession`/`ExecuteNativeStop`); real `Observe` and `StartSession` are not executed, so their generation advances are fixed by source-contract tests only. `input_api_attempts` unchanged after preflight is a seam-level check plus a source-contract (no increment call exists in the preflight path).
- Everything native (compile, harness, seams, ASan/UBSan, MSVC /W4 /sdl) is **NOT_RUN locally**. Fresh ordinary macOS/Windows CI at the final head, independent review and the S4/V2/Main interlocks remain required. N2b must still add Main-side use, mandatory tickets and the approval ticket; none of that exists here.

## N2b-1 Main-side preflight and ordinary ticket on 2026-10-03

Scope: Main host adapter only (`computer-use-native-host.ts`, optional `preflight` on the addon type). The capability is the presence of the exported `preflight` method on a darwin addon; no handshake, loader, contract, protocol, renderer, `.mm`/`.cc`, flag or Windows change was needed (the native handshake key set is fixed and a new key would need a native change).

Behavior: when a darwin addon exports `preflight`, every `dispatch` first calls it with the same request (no ticket), validates the closed receipt (fixed 10 keys, classifierVersion 1, request/session/cancelEpoch/observationRevision echo, decision table, 64-hex ticket only for `ordinary`, non-regressing input count) and then either dispatches with the single-use `ticket`, or returns the native `blocked`/`takeover`/`denied` result and reason without dispatching. `replay` dispatches without a ticket so the native cache answers (replay is answered before the ticket check). A malformed receipt, `single_use_approval` or any unknown decision throws `native_preflight_invalid` before any dispatch; the ticket never appears in an error. Preflight throws map through the existing pre-dispatch failure classifier. Ticket "mandatory" is enforced Main-side only: an addon without `preflight` (older native, Windows) keeps the legacy path, and native still accepts a missing ticket.

Non-goals (N2b-2 and later): approval ticket and trusted-activation UI, native-side mandatory ticket (`.mm`), Windows preflight, E1-E5 precision, manifest/ruleset interlocks, V2 flag. Limits: a `replay` followed by cache eviction before dispatch would run the legacy path; this window is accepted because request ids are single-use in Main. Verification is TypeScript only (host/native/controller suites, typecheck, lint, format); no native compilation was involved.


## N2b-2 single_use_approval as a closed no-input pause on 2026-10-04

Scope: Main host adapter only (`computer-use-native-host.ts` and tests). No controller, contract, renderer, IPC, `.mm`/`.cc`/`.h` or Windows change.

Behavior: a darwin preflight receipt with `decision: 'single_use_approval'` is accepted only as the exact tuple `ticket === null`, `reasonCode === null`, `deniedResult === null` (plus the existing common checks: classifierVersion 1, fixed 10 keys, request/session/cancelEpoch/observationRevision echo, non-regressing input count). It is returned through the existing `refused` path as `paused` with the fixed Main-owned reason `native_single_use_approval_unavailable`; the native reason is never forwarded, `dispatch` is never invoked, so input is always zero. Any other shape (ticket present, reason or deniedResult present, version 2, extra key, mismatch) still throws `native_preflight_invalid`. This replaces N2b-1's behavior for this decision, where the throw made the controller record `unknown_effect`/`native_ack_unknown` for an action that was never dispatched. The controller needs no change: `paused` is audited as `rejected`, does not spend or install a plan grant, and pauses the session; the renderer keeps its generic paused display.

Decisions taken by the parent: reasonCode accepts null only (stricter; the native closed table does not exist yet); result is `paused`; the reason name is fixed as above; the early landing is justified by the unknown_effect misrecording fix. The production native never returns this decision (classifier v1 cannot reach it), so the branch is exercised only by fake addons.

Still NOT done (ADR S4-4 remains open): the approval ticket (native type, slot, issue, consume), the trusted-activation approval card wiring, post-approval re-preflight with a new request id, native-side mandatory ticket for approval-class targets, classifier v2 (E1-E5) and the Finder measurement (S4-5), Windows preflight, manifest/ruleset interlock and the V2 flag. Entry condition for the next slice (N2b-3): the S4-4 approval ticket contract (issuer, TTL/generation handling and re-preflight after approval, bound fields, approval unit for type, approval expiry, audit request id) is appended to the ADR and re-reviewed first. Known open problem for that slice: controller full_access_app computes `actionMayNeedApproval` as false, so it must not rely on full_access_app or a plan grant to skip approval.
