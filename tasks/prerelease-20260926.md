# 0.7.0-beta.11

2026-09-26 のユーザー依頼「B. bug 19件をすべて実装してマージ。この分が最新リリースに反映されていないのであれば次のリリースを実行して」に基づき、
beta.10 公開後に main へ入った修正を評価用ベータとして公開する。最新の公開物 v0.7.0-beta.10（9fa65a7）には含まれていない。base 0.7.0 は維持し、未使用番号 beta.11 を一度だけ採用する。

v0.7.0-beta.10 以降の配布変更:

- Team の完了判定と統合
  - #590 (#568): 統合されずに終わった（未統合・片付け失敗の）Worker の書き込みの Saga で、Leader の Turn を失敗させない。
  - #591 (#569): 統合後に worktree を片付けられなかった repository だけを隔離し、理由を日本語で記録する。残りの repository も片付ける。
  - #592 (#589): 書き込みの Worker を中止したら隔離を quarantined にして、残った worktree の一覧に出す。
  - #597 (#587): 書き込みを頼まれた Manager は、自分の変更か、この実行の間に部下が完了させた書き込みがあるときだけ成功にする。
  - #598 (#585): Claude・Grok の Worker で、ツールの直後に改行なしで始まる完了条件ごとの報告を読み取る。
  - #599 (#584): Main が書き込みを確かめて失敗にした試行の終了理由を「書き込みを確認できず失敗」（`workspace_write_unverified`）として、Worker の失敗の報告と区別する。
- worktree と解雇
  - #595 (#580): 手で消した worktree でも、Git の記録に submodule の中身（Worker のコミット）が残っていれば、自動の片付けで登録を外さない。一覧は submodule ありを表示し、破棄は強い警告を出す。
  - #596 (#588): 回収で登録を外せなかった理由を診断に1件残す（同じ理由はプロセスの中で1回）。
  - #604 (#586): 前の Turn で採用した Worker にこの Turn で割り当ててから解雇しても、「Worker が1名も作成されませんでした」で失敗にしない。
- Worker の承認カード
  - #605 (#572): Worker を解放したら、その呼び出しの承認待ちカードだけを取り消し（決定なし・grant なし）、ほかにカードが無ければ Leader の Turn を実行中に戻して完了できるようにする。
  - #609 (#573): 承認カードを待つ間は Worker の無進捗（15分）の時計を止め、カードが片付いたら残り時間で再開する。heartbeat と実行時間の上限（既定30分、判断待ちも含む）は止めない。
- Managed Local の Worker
  - #612 (#570): 直接メッセージは読み取り専用として Task の Workspace を渡し、旧形式の Mission・Graph の書き込み工程は隔離 worktree を Workspace にして渡す（「External API Worker cannot write…」で失敗しない）。
  - #614 (#574): 読み取りの拒否やパッチの不一致などのワークスペースのツールの失敗を、Leader と同じ変換でツールのエラーとして返して続ける。
- Graph Mission
  - #594 (#556): Graph の工程で CLI の終了を確かめられない間は、資源の予約を解放しない（再開・制約の更新・取り消しも同じ）。
  - #610 (#606): Graph の工程の Manager が部下に書かせた変更も、工程の変更範囲で検査し、範囲外は統合しない。
- 検出と表示
  - #600 (#581): 起動時の Grok CLI の検出で CLI の終了を確かめられなくても、応答した状態（ready／認証が必要）を使う。設定の「再読み込み」で Codex・Claude・Grok の検出をやり直せる。検出が残した隔離フォルダは、そのプロセスの停止を確かめてから片付ける。
  - #601 (#571): 統合の順番待ちの Repository の状態を「統合の順番待ち」と表示し、再開待ちには統合を再開する操作を出す。
  - #602 (#583): Chat の作業履歴でも、Team 画面と同じ日本語の終了理由を表示する。
  - #603 (#579): Worker カードの「統合済み」を、残った worktree の一覧と同じ確認結果（Workspace の履歴に入っているか）で表示する。
- テストの安定化（配布物の動作は変わらない）
  - #593 (#576): 圧縮データ検査と結合テストの時間切れを runner の混み具合で起きにくくする。
  - #607: Team MCP ブリッジのテストで応答を待つ上限を延ばす。

version 更新はこの PR のみ（`apps/desktop/package.json` と lockfile）。配布・検証の方針は
`tasks/prerelease-20260922.md` の beta.5 の記載を引き継ぐ（merge 済み commit に tag を付け、release workflow の Draft で全 asset・version/tag/commit・更新 manifest・macOS の署名・notarization・cleanup を確かめてから、`--latest=false` の pre-release として公開する）。
