# BlenderでSprint Coder Teamの編集を表示する

Sprint Coder Teamの10人のWorkerが、同じBlenderシーンの別々の箇所を観察して編集する。人間が全景を動かしている間も、担当者の3D座標と各Workerの画像が見える。

- Blenderアドオンは担当オブジェクト、カーソル、独立視点を管理する。描画時にGPUで視点画像を取得し、編集はメインスレッドで処理する。
- Sprint CoderのMainは認証済みのTeam Workerに、観察と限定された編集のツールを提供する。Worker IDと担当をサーバー側で結び付ける。最初の観察では利用者が選んだメッシュを名前で指定できる。割り当て後はWorkerのIDに固定する。
- 接続はユーザーが明示的に開始する。シーン切り替え、切断、Worker停止の際に所有権と保留中の操作を無効にする。操作は対象オブジェクトと観察時の状態を再確認してから反映する。
- Phase 1で扱う編集はオブジェクト移動とメッシュ面の押し出し。Blender本体の変更、任意Pythonの実行、公開ネットワークへの接続は対象外。
- 受入では10人の視点とカーソルが実画面に出ること、異なる担当箇所への編集が同じシーンに反映されること、Workerが更新後の画像を見て次の操作を決められることを確認する。衝突、停止、シーン切り替え、スコープ外の変更は境界テストで確認する。

## Blender側の検証

macOSのBlender 5.1.2で、検証用の10メッシュに対してカーソルと異なる視点を10件ずつ目視した。GPUから得た10件のPNGが互いに異なることも確認した。バックグラウンド試験は移動、押し出し、担当外の編集拒否、古い観察と再使用の拒否を対象にする。

```sh
blender --background --factory-startup --python-exit-code 1 --python integrations/blender/tests/test_addon.py
blender --command extension build --source-dir integrations/blender/sprint_coder_team
```

## 接続と使い方

1. アドオンを標準のBlenderに追加し、対象シーンで1〜10個のメッシュを選択する。
2. 3Dビューポートのサイドバーで **Team → Start pairing** を押してコードをコピーする。
3. Sprint Coderの対象Taskで **Team → ポリシー設定 → Blender** を開き、**コピーしたコードで接続** を押す。コードの手入力もできる。接続はこのTaskに限定される。
4. TeamにBlender作業を指示する。名前で依頼した場合、Workerは最初の観察で対象を指定できる。各Workerは担当メッシュの画像と面の位置・法線を取得し、移動または押し出しを行う。必要な角度に変えて再撮影できる。
5. 作業を終えたら接続を解除する。選択対象を変更するときはBlenderで新しいペアリングを開始する。

ペアリングコードは一度だけ使え、BlenderとSprint Coderはループバックで通信する。CLIのWorkerはTeam MCPの登録から、ProviderのWorkerはTeam実行時のIDから担当を決める。観察トークンはWorkerとTurnに束縛し、編集後は再観察を要求する。Provider側は画像送信を既存の送信ポリシーに通す。画像対応を確認できた外部接続では送信先とモデルを表示し、画像ごとに承認する。

移動は親子関係のない対象に限る。BlenderのグローバルUndoが有効な場合、Workerの編集は個別に履歴に記録される。Undo・Redoの際は、古い観察を無効にするためペアリングを解除する。

## Team側の検証

- macOSの隔離開発版でBlenderのTeamパネルからペアリングを開始し、Sprint Coderで10メッシュの名称が表示されることと解除を確認した。接続コードは検証用のものを入力しており、アプリ間のクリップボード操作は未確認。
- 認証済みTeam MCPに接続した10個のWorker IDで、Blender 5.1.2への観察 → 押し出し → 再観察を同時に実行した。10個すべてで面数が増え、画像も変わった。別Team、別Worker、登録解除済みのTurnは拒否された。
- Codexの画像添付、Provider画像の承認・拒否、CLIモデルに応じた実行時のツール公開を対象テストで確認した。停止時はBlender側の担当解放を確認してから完了を返し、別のWorkerへ同じ対象を割り当てられる。一時的に解放応答が取れない場合は停止未確認となり、停止の再試行または後続の割り当てで再確認する。ループバック接続が拒否され、Blenderのリスナー終了を確認できた場合は、元の接続を無効化して停止を完了できる。

## 街区デモ

`integrations/blender/demo/build_city_block.py` で、屋根やひさしなど10個の編集対象を含む自己完結型の街区を生成できる。保存済みの街区で10本のカーソルと10枚の独立視点を目視した。街区での継続的な操作レスポンスは計測していない。

生成する場合は、新規の出力ファイルを指定する。

```sh
blender --background --factory-startup --python-exit-code 1 --python integrations/blender/demo/build_city_block.py -- /path/to/new-city-block.blend
```

## 実Codex CLI受入 2026-11-28

利用者が許可した使い捨てシーンで、macOS arm64、Blender 5.1.2、Codex CLI 0.170.0、GPT-6.2 Solを使用。Sprint CoderのCodexアダプターと認証済みTeam MCPを通して10個の独立したWorker Turnを並行起動した。各Workerが別の角度・担当メッシュの画像から赤か青かを見て、対応する移動量を実行し、再観察した。10/10で各1回の編集と期待位置を確認した。取得画像は計21枚。Blender上の位置と画像の識別子を照合した。試験は25.8秒で完了した。

対象ファイルは `apps/desktop/src/main/blender-team.test.ts`。実AI試験は `SPRINT_CODER_TEST_BLENDER_CODEX` を指定したときだけ実行する。上記試験では捨てシーンの画像送信の事前許可を試験側で与えた。CLIの画像ごとの製品ダイアログと、コピーしたコードで接続する操作は実画面で未確認。ローカルAI試験は利用者の指示で中止した。

## 各Workerのカーソルで選んで編集する

各Workerの画像上の座標をBlenderの3D空間へ変換し、カーソル移動、クリック選択、選択箇所の編集を別々の操作として扱う。面と頂点は実際のメッシュから特定する。共有ビューポートにはWorkerごとのカーソルと選択のハイライトを表示する。初期範囲は頂点移動と面の押し出し。1つのOSポインターに入力を集約せず、Workerごとの独立したカーソルで操作する。

CLIとProviderのWorkerは既存の認証・画像承認を通る。クリックと編集は最新の観察トークンと担当に束縛される。対象外、遮蔽、古い選択、停止後の要求は編集できない。Blender上の10個の異なる対象について、視点座標から選択し、選んだ頂点または面だけが変わることを自動試験する。操作者から見える動きは実画面で確認する。

カーソル編集はBlenderアドオンv0.2.0を使う。Workerは `blender_observe` → `blender_pointer` の移動と選択 → `blender_edit` の頂点移動または選択面押し出し → 再観察の順で操作する。頂点・面を選ぶ対象は、表示用モディファイアのないオブジェクトモードのメッシュに限る。

Codex CLIの実AI試験では初回10体中8体が完走した（頂点移動5体、面の押し出し3体）。未完走の2体を再試行し、面の押し出し1体が追加で完走した。残る1体は観察までで編集に到達しなかった。実AIが10体すべて完走することは未確認。街区デモの動画は、Blenderの実際のカーソル操作とメッシュ編集を、固定のテスト操作で再現したもの。

## 空のシーンからの実AI録画

`create_base` はペアリングした空のメッシュに、指定した幅・奥行きの底面を1枚作る。配置と素材を持つ空の担当メッシュ10件だけを用意して録画を始め、Codex CLIのWorkerが底面を作成して、カーソルで面を選択し、それぞれ押し出した。4体はさらに頂点を選んで屋根の角を動かした。最後の観察まで10体が成功し、保存したシーンで9棟と道路を確認した。録画にはBlenderが実際に描画したフレームのみを使った。

以前に観察で終了したWorker（0始まりの番号2）を同じ立方体・視点で再度実行すると、クリック・押し出し・再観察まで成功した。以前のログには成功した操作しか残っておらず、その実行が止まった直接原因は確定できなかった。今回から試行・拒否の分類も残す。街区試験の初回は1体の底面作成が拒否されたため、最新の観察トークンを使う手順と、同じ録画内での未完了操作の再開を追加して再実行した。最終録画では再開を使わず10体すべてが完走した。

### 屋根・窓・路地のある街区

`detail_face` はクリックで選んだ面に、屋根、窓列、入口、または道路の付帯形状を1操作で追加する。屋根と道路は上面、窓と入口は垂直面を要求する。選んだ面の頂点座標が変わっている場合は拒否する。形状は担当メッシュに追加し、共有メッシュ・シェイプキー・頂点親子付け・有効な表示モディファイアがある場合の編集は従来どおり拒否する。

空の担当メッシュ10個で開始した実Codex録画では9棟に屋根・窓列・入口、道路に歩道・路地・白線ができた。10体の操作ログに38件の有効なクリック選択を記録した。2体は担当を保ったまま同じ録画中に再開し、全員が最終観察まで完走した。
