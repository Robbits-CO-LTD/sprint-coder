### Runner ownership and distribution preflight

The reusable runners now require the exact approved lane and dependency root from `dflash-windows-guard.cjs`. An operator must explicitly provision `.dflash-acceptance-owner.json` in that owned lane and `.dflash-profile-owner.json` in its dedicated profile; the runners never adopt an unmarked existing profile. Both markers must exactly match `{schemaVersion: 1, owner: "issue-434-20260915", lane, profile, version: "0.7.0-beta.3", source: "5b20208eb7b4f7697105dca2bf9436da3aeec910", zipSha256: "663a29379f9908f1f9d0beea1e7d4eb89df526748d8326e198f19fe97cf3daeb"}`, with the approved absolute lane/profile paths. Missing/mismatched markers, alternate roots, path aliases, junctions/symlinks and hardlinked files are rejected before loading dependencies or writing runner evidence. Main's already-verified dedicated Windows lane was explicitly marked during this follow-up; the old acceptance evidence remains unchanged.

Before any fuse flip or app launch (including a restart), the shared guard verifies the fixed ZIP digest, all archive entries and the absence of extra files, the fixed app.asar digest, and the version inside its package.json. The expected version/source binding is pinned to the release ZIP above. Download accepts the original exe or the one permitted inspector change, verifies again after a flip, and acceptance requires that inspector change already be present. No runtime, native or application-code replacement is allowed. The ScheduledTask launcher also checks ownership before registering a task.

`verify-dflash-distribution.ps1` uses this same guard for executable comparison. It compares 1 MiB chunks with native `Buffer.equals`, enumerates offsets only inside unequal chunks, locates the unique Electron fuse sentinel, validates wire version/count, and permits exactly index 3 changing from 48 to 49. Length changes or any other changed byte fail. The current Windows artifact passed: 228 chunks compared, 1 unequal chunk, exactly offset **193579845** changed, forbidden changed bytes **0**. Updated read-only evidence is preserved locally as `test-results/issue-434-windows/distribution-byte-verification.json`. No GUI, model download or inference was repeated. ### Pinned native and verification boundaries

- [`llama-model-loader.cpp:873`](https://github.com/ggml-org/llama.cpp/blob/5266f24da75dc449bd56cbed7addb9c8e4a6a73e/src/llama-model-loader.cpp#L873) checks expected tensor dimensions and throws on missing/wrong-shape tensors. DFlash constructs expected tensors in `src/models/dflash.cpp:94` onward. These are real native checks, not proof that every arbitrary pair is compatible.
- DFlash shares the target token embedding/output at [`dflash.cpp:672`](https://github.com/ggml-org/llama.cpp/blob/5266f24da75dc449bd56cbed7addb9c8e4a6a73e/src/models/dflash.cpp#L672) and line 772; [`ggml.c:3282`](https://github.com/ggml-org/llama.cpp/blob/5266f24da75dc449bd56cbed7addb9c8e4a6a73e/ggml/src/ggml.c#L3282) asserts compatible multiplication dimensions. `llama-context.cpp:1178` bounds extracted target-layer IDs. An incompatible model can therefore fail load or abort its owned sidecar; this is not silently treated as successful inference.
- [`server-context.cpp:3896`](https://github.com/ggml-org/llama.cpp/blob/5266f24da75dc449bd56cbed7addb9c8e4a6a73e/tools/server/server-context.cpp#L3896) calls `common_sampler_sample_and_accept_n` with `ctx_tgt`; [`sampling.cpp:678`](https://github.com/ggml-org/llama.cpp/blob/5266f24da75dc449bd56cbed7addb9c8e4a6a73e/common/sampling.cpp#L678) samples the target token and stops accepting the proposal at the first disagreement. A poor draft is not a source of unchecked output tokens.
- Product `managed-local-runtime-supervisor.ts` checks listening/auth/health and stops the owned child on startup failure. `managed-local-self-test.ts:30` requires exact text and structured draft counts before calling `onLoaded`; `ManagedLocalController.verify` stores `tools` only after the full tool round-trip and releases its lease in `finally`. Loaded/verified reuse remains bound to the actual pair hashes, settings and fixed runtime.
