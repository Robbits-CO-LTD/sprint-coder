# macOS のデスクトップ操作の残り（段階 4）の実機の確認（2026-11-16）

[Issue #1320](https://github.com/Robbits-CO-LTD/sprint-coder/issues/1320) の残りと [Issue #1329](https://github.com/Robbits-CO-LTD/sprint-coder/issues/1329) を直した時の、実アプリでの確認の記録。各 PR のコメントに書いた結果を、1 か所にまとめたもの。

## 環境

- macOS 27.0.1（Apple シリコン）。開発版（dev build）。隔離した profile（初回のセットアップを画面で通した新しい profile）。
- 操作は Computer Use（開発エージェントが実アプリをクリック・入力）。shell は、起動と、保存ファイル・log・窓の一覧の照合に使った。
- 実際の AI は Codex CLI の Runtime（設定のモデルは「Auto」。実際に使われたモデルの名前は取れていない）。CLI の定額の利用枠で、API の課金は無い。
- この日は、オーナーが同じ Mac を使っていた。全画面の Chrome と通常のデスクトップを行き来していたので、一部の確認は通常のデスクトップに居る間だけ行えた。

## 未 merge の物

### Team のカーソル（#1335）

- CLI の単位（build を開発版の Electron の子として実行）: 描画の子の起動、agent ごとの描画、`retire` でその agent だけが終わること、Main の終了で 1 秒以内に終わることを確認（1 つ目の commit）。
- カーソルの重なり（2 つ目の commit）: 画面上の窓の順番（前から後ろ）が「利用者の Chrome ＞ カーソルの窓 4 つ ＞ 計算機 ＞ ほかの窓」。カーソルの窓の層は計算機と同じ。前面のアプリは変わらなかった。
- 製品の経路（1 つ目の commit）: Project を選んだ Task で、実際の AI が計算機を起動・操作し「7×8＝56」と答えて閉じた。この時、描画の子を起動した最初のクリックが 5 秒待たされ「失敗」と記録された（2 つ目の commit で直した）。アプリの終了で描画の子が終わることを確認。
- 未実施: 2 つ目の commit の build での製品の経路、Team の Worker での確認。
