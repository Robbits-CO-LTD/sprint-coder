# macOS のデスクトップ操作の、前面を使う操作の確認（2026-11-17 夜）

それまで確かめていなかった「前面を使う操作」（実際の pointer と key の入力、窓を前に出す・最小化から戻す・最大化）の、実機の記録。オーナーから、その場で了承（「今どうぞ」）をもらって実行した。常の了承ではない。

## 環境と、この記録の位置づけ

- macOS 27.0.1（Apple シリコン）。開発版（dev build）。build は、main（`24b21641`）と、直した後の 2 つの branch。
- 「CLI を直接実行」は、実行ファイルを、開発版の Electron の子として 1 コマンドずつ実行したもの。
- 試験用のアプリ（自作）は、ボタン・文字の欄・スライダー・pointer が乗ると分かる箱を 1 つの窓に持ち、受け取った event を全部記録する: 実際の mouse と key の event（accessibility の操作では起きない）、部品の動き、前面になった・最小化された・大きさが変わった。CLI の言う結果とは別に、何が届いたかを確かめるために使った。
- 製品の経路は、開発版の Sprint Coder（隔離した profile、隠した状態で起動）の中の実際の AI（Codex CLI、GPT-5.6-Terra を明示、設定は「確認する」）。入力とカードの許可は、debug の口（remote debugging）からの入力イベントで行った。Computer Use での操作ではないので、**製品の経路の PASS は補助の結果**。

## 1. 前面を使う操作が届くこと（CLI を直接実行、main の build）

| 操作                                               | CLI の結果                           | 試験用のアプリの記録                                         | 前面・pointer                         |
| -------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------ | ------------------------------------- |
| 裏の `click`（比べるため）                         | 成功                                 | ボタンの動きだけ。mouse の event は無く、アプリは前面でない  | 変わらない                            |
| `focus-window`                                     | 成功                                 | 前面になった                                                 | 試験用のアプリが前面                  |
| `click --headed`                                   | 成功                                 | ボタンの位置で mouse の down と up、ボタンの動き             | pointer がボタンの中心へ動いた        |
| `type`（`--headed` なし）                          | 成功（確かめ済み）                   | 文字が入った。key の event は無い                            | 変わらない                            |
| `type --headed`                                    | 成功（確かめ済み）                   | key の event 1 つ（文字列を運ぶ）、文字が入った              | 変わらない                            |
| `press tab --headed`                               | 成功                                 | Tab の key の event                                          | 変わらない                            |
| `hover --xy --headed`                              | 成功                                 | 箱に pointer が入った                                        | pointer が箱の中へ動いた              |
| `drag --from <ref> --to-xy --headed`               | 成功                                 | スライダーの上で mouse の down、値が 10 から 83 まで上がった | pointer が落とす先へ動いた            |
| `maximize`（辞書の窓。裏にある時と、前面にある時） | 成功（結果は確かめていない、と返る） | —                                                            | 窓が画面いっぱい（work area）になった |

- 試験用のアプリの窓に対する `maximize` だけ、窓は広がったのに 5 秒で `TIMEOUT` を返した。辞書の窓では起きない。試験用のアプリの側の事情と見て、直していない。
- `restore` は、`maximize` で広げた窓を元の大きさに戻さない（成功を返し、窓はそのまま）。macOS の `maximize` は位置と大きさを設定するだけで、前の大きさを覚えていない。同梱の説明書には、前から「`restore` は un-maximize を約束しない」と書いてある。変えていない。

## 2. 最小化と復元が、動いたのに失敗を返す（[PR #1360](https://github.com/Robbits-CO-LTD/sprint-coder/pull/1360)）

辞書の窓で、CLI を直接実行。

| 操作                    | main の build                                                                     | 直した build                  | 窓の実際の状態（`list-windows`） |
| ----------------------- | --------------------------------------------------------------------------------- | ----------------------------- | -------------------------------- |
| `minimize`              | exit 1、`TIMEOUT`「Accessibility surface read failed for AXMinimized」（0.57 秒） | exit 0、確かめ済み（0.85 秒） | どちらも最小化された             |
| `restore`（最小化から） | exit 1、同じ `TIMEOUT`（0.58 秒）                                                 | exit 0、確かめ済み（0.99 秒） | どちらも元に戻った               |

- 原因: アプリは、窓を Dock へ入れる・戻す animation の間、accessibility の読み取りに「今は答えられない」と返す。結果を確かめる待ちが、その 1 回目の失敗でやめていた。

## 3. hover と drag の後の Team のカーソル（[PR #1359](https://github.com/Robbits-CO-LTD/sprint-coder/pull/1359)、Issue #1351）

CLI を直接実行。Team のカーソルを有効にした session。試験用のアプリの窓 F と、F のボタンに重なる位置の辞書の窓 D。操作の後に D を前に出して、画面の窓の順番（前から後ろ）を記録した。c はカーソルの窓。

| 操作                                                     | main の build                                      | 直した build |
| -------------------------------------------------------- | -------------------------------------------------- | ------------ |
| 裏の `click`（D が前）                                   | `DccccF`（カーソルは D の下、F のすぐ上。layer 0） | 同じ         |
| `hover <ref> --headed` の後に D を前に出す               | `ccDF`（カーソルが D の上。layer 103）             | `DccF`       |
| その 3 秒後                                              | `ccDF`                                             | `DccF`       |
| `drag --from <ref> --to-xy --headed` の後に D を前に出す | `cccDF`（layer 102〜103）                          | `DccF`       |

- 落とす先も部品の `drag`（`--to <ref>`）は測っていない。

## 4. 製品の経路（実際の AI、main に 2 の修正を足した build）

「計算機を起動して前面に出し、実際のキー入力で 7×8= を計算して、結果を教えて。前面を使ってよい。最後に閉じる」と頼んだ。

| 順   | AI のコマンド                                             | カード                                                                                                                                      | 許可の後                                 |
| ---- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 1    | `launch Calculator --activate`                            | 「アプリを起動します」「前面を使います」「起動した窓が前面に出ます。」（「今回のみ許可」と「拒否」の 2 つ）                                 | 計算機が前面になった                     |
| 2〜5 | `--headed press 7`、`shift+8`、`8`、`=`（`--app 計算機`） | 「キーを押します」「前面を使います」「押すキー「…」」「窓が前面に出て、マウスとキーボードを使います。入力中は触らないでください。」（2 つ） | 計算機が前面のまま                       |
| 6    | `snapshot --app 計算機 --window-id …`                     | 「画面を読みます」（3 つ）                                                                                                                  | —                                        |
| 7    | `close-app Calculator`                                    | 「アプリを閉じます」「マウスとキーボードは使いません」（3 つ）                                                                              | 計算機が終わり、前面は元のアプリに戻った |

- AI の答え: 「7×8 の計算結果は 56 でした。」7 つとも exit 0。
- 前面を使うカードには「Task 中許可」が出ない（1 回ずつの許可だけ）。

## 確かめていないもの

- 製品の経路で、実際の AI が `hover`・`drag` をした時のカーソル（3 は CLI を直接実行）。Computer Use での製品の経路の確認。
- `right-click`、`double-click`、`scroll`、`key-down`・`key-up`、`mouse-*` の `--headed`。
- 必須 Skill の正式な lane。Windows の実機（Windows の挙動は変えていない）。

## この確認の間にオーナーの Mac で起きたこと

- 約 15 分のあいだ、試験用のアプリ・辞書・計算機が何度か前面になり、pointer が動き、key の入力が試験用のアプリと計算機に入った。
- 辞書の窓の位置と大きさは、元に戻してから閉じた。試験用のアプリ、辞書、計算機、試験用の Sprint Coder は終了した。
