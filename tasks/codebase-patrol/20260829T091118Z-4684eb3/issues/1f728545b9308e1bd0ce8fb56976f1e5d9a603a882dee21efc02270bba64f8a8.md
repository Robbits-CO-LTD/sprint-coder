## 症状と影響

Managed Localモデルのartifact responseがContent-Length不一致、resume identity不一致、または実byte超過で拒否されても、response bodyがcancelされません。GGUFは大容量のため、jobがfailedになった後も不要なdownloadとconnection資源が残る可能性があります。

## 再現手順

1. install planは10 byteを期待する。
2. fixture fetchは`Content-Length: 11`と、cancel呼出しを記録する継続streamを返す。
3. `LocalModelDownloadManager.run`を実行し、job stateとstream cancel状態を確認する。

Node 22でjobは`failed`になりましたが、response streamは`cancelCalled=false`でした。

## 期待した結果と根拠

artifact identity/size検証でresponseを拒否した時点でbodyをcancelし、それ以上のdownloadを停止するべきです。pause/cancel操作も同じfetchをAbortControllerで停止する契約を持っています。

## 実際の結果

job stateだけがfailedへ遷移し、response bodyは未cancelのままです。reader取得後のbyte超過でも、finallyはpartial file handleだけを閉じ、readerをcancel/releaseしません。

## 根本原因

`LocalModelDownloadManager.downloadArtifact`のresponse検証とreader loopに、異常終了時のbody/reader cancel処理がありません。reader自体も正常・異常を問わず明示解放されません。

### 原因経路

artifact fetch → size/resume検証失敗またはstream byte超過 → exception → DB jobはfailed → response bodyは未cancel。

### 確認した証拠

- Runtime: Content-Length不一致fixtureで`failed`と`cancelCalled=false`を同時に観測した。
- Code: header検証はreader取得前にthrowし、reader loopのfinallyはfile handleだけを閉じる。
- State: managerはfailureを正しくDB stateへ変換する一方、network streamへ終端操作を行わない。

### 除外した代替原因

- job失敗処理の欠落ではない。fixture jobは`failed`へ遷移した。
- caller cancelのAbortController不足ではない。問題はremote responseの検証失敗であり、caller signalはabortされていない。

## 影響範囲と非対象

Managed LocalのGGUF/mmproj artifact downloadとresume検証が対象です。公開catalog metadata readerは別Issueです。
